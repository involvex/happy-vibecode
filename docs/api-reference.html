Happy Vibecode

API Reference

The Happy Vibecode API is built with Hono and mounted at /api/* in the Cloudflare Worker. All endpoints require authentication unless otherwise noted.

Authentication
Most endpoints require a valid session token obtained via Better Auth (OAuth or email/password). Include the token in the Authorization: Bearer <token> header.

Health Check

GET /api/health

Returns service health status. No authentication required.

Response 
{
  "status": "ok",
  "timestamp": "2026-03-29T10:00:00.000Z"
}

Authentication

All /api/auth/* routes are handled by Better Auth. See the apps/web/worker/auth.ts configuration.

Method Endpoint Description
POST /api/auth/sign-in/email Sign in with email/password
POST /api/auth/sign-up/email Register with email/password
GET /api/auth/sign-in/social/github Initiate GitHub OAuth
POST /api/auth/sign-out Sign out current session
GET /api/auth/session Get current session info

Sessions

Manage agent sessions — the connection between a user and an AI coding agent.

List Sessions

GET /api/sessions

Returns all sessions for the authenticated user. Filter by status with ?status=connected.

Response 
{
  "sessions": [
    {
      "id": "uuid",
      "userId": "user-id",
      "agentType": "gemini",
      "connectionStatus": "connected",
      "roomId": "room-id",
      "workspaceId": "workspace-id",
      "model": "gemini-2.5-pro",
      "startedAt": "2026-03-29T10:00:00.000Z",
      "endedAt": null,
      "metadata": "{}"
    }
  ]

Create Session

POST /api/sessions

Request Body 
{
  "agentType": "gemini",
  "roomId": "optional-custom-room-id",
  "metadata": { "key": "value" }
}

Get Session

GET /api/sessions/:id

Returns all messages for a session, ordered by timestamp.

Rate Limiting

All authenticated endpoints are rate limited. Response headers include:

  • X-RateLimit-Limit — Maximum requests per window
  • X-RateLimit-Remaining — Remaining requests in current window
  • X-RateLimit-Reset — Unix timestamp when the window resets
  • Retry-After — Seconds until retry (on 429 responses)
429 Response 
{
  "error": "Rate limit exceeded",
  "retryAfter": 45,
  "limit": 30,
  "window": 60
}

Error Handling

All errors follow a consistent JSON format:

Error Response 
{
  "error": "Human-readable error message",
  "details": [] // Optional: validation error details
}
Status Meaning
400 Bad request (validation error)
401 Unauthorized (missing or invalid token)
403 Forbidden (insufficient role/permissions)
404 Resource not found
409 Conflict (e.g., already subscribed)
429 Rate limit exceeded
500 Internal server error
